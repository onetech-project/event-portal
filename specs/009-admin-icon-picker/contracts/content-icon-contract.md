# Contract: Content Block `icon` Field & Icon Catalog

**Feature**: 009-admin-icon-picker | **Date**: 2026-08-05

This feature changes **no endpoint paths, methods, or JSON shapes**. It enlarges the
value domain of one field and formalizes the catalog artifact that binds frontend and
backend to the same domain.

## 1. Affected endpoints (shapes unchanged)

Admin (authenticated), under `/api/v1/admin/events/:event_id`:

| Endpoint | Body field | Before | After |
|----------|-----------|--------|-------|
| `POST /activities`, `PUT /activities/:id` | `icon: string \| null` | one of 20 fixed keys | any key in the Icon Catalog |
| `POST /guidelines`, `PUT /guidelines/:id` | `icon: string \| null` | one of 20 fixed keys | any key in the Icon Catalog |

Guest reads (`GET /api/v1/events/:slug` content payloads) and admin list reads return
`icon` exactly as stored — `string | null` — unchanged.

Guest-star endpoints have no `icon` field and are untouched.

## 2. Validation contract (unchanged semantics, enlarged set)

- `icon` absent, `null`, or `""` → accepted, stored as NULL ("no icon").
- `icon` = key present in the Icon Catalog → accepted, stored verbatim.
- `icon` = anything else → **HTTP 400**, application code **400004**
  (`apperr.CodeUnknownIcon`), message directing the admin to pick from the recognized
  set. This is the existing tested contract and MUST NOT regress.

## 3. Icon Catalog artifact contract

File: `backend/internal/event/iconkeys/icon_keys.txt`

- Generated by `frontend/scripts/generate-icon-keys.mjs`; MUST NOT be hand-edited.
- Content: exactly the key set of the installed `lucide-react`'s `dynamicIconImports`,
  sorted lexicographically, one key per line, LF line endings, no blank lines, no
  comments. Keys match `^[a-z0-9]+(-[a-z0-9]+)*$`.
- Checked into the repository; regenerated in the same commit as any `lucide-react`
  version change.

**Conformance tests** (both must exist and pass):

- Frontend (vitest): `Object.keys(dynamicIconImports).sort()` deep-equals the file's
  lines — catches upgrade drift in either direction.
- Backend (go test): embedded set is non-empty (≥ 1,000 keys) and contains all 20
  legacy keys: `music, mic, utensils, cup-soda, gamepad-2, palette, camera, gift, star,
  heart, ticket, map-pin, clock, info, shield, ambulance, car, cigarette-off, id-card,
  ban`.

## 4. UI contract (admin picker & renderers)

- The picker MUST only offer keys that pass validation (subset of the catalog).
- Selecting an icon then saving MUST round-trip: the stored key renders the same glyph
  in the admin list and on the public event page.
- Clearing MUST submit `null` (not `""`, not a sentinel key).
- Renderers (`ContentIcon`) MUST render a generic fallback (`info` glyph) for any
  stored key not resolvable in the installed icon set, and MUST render nothing for
  NULL — never an error state.
