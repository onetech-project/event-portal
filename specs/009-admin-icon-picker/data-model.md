# Data Model: Admin Visual Icon Picker

**Feature**: 009-admin-icon-picker | **Date**: 2026-08-05

## Database

**No schema change.** SCHEMA.md remains authoritative and untouched. The `icon` column
on `event_activities` and `event_guidelines` stays a nullable text field holding a
catalog key or NULL. Only the set of values accepted at the API boundary grows.

## Entities

### Content Block — Activity (existing, unchanged storage)

| Field | Type | Rules |
|-------|------|-------|
| id | uuid | PK |
| title | text | required, sanitized |
| description | text | required, sanitized |
| icon | text, nullable | NULL/empty = no icon; otherwise MUST be a key in the Icon Catalog (else 400004) |
| position | int | ordering within the event |

### Content Block — Guideline (existing, unchanged storage)

Same as Activity minus `title`. Guest stars have no icon field and are out of scope.

### Icon Catalog (new — generated artifact, not a table)

The recognized set of icon keys. Single source of truth: the installed `lucide-react`
package's `dynamicIconImports` key set (2,007 keys at v1.28.0).

| Representation | Location | Consumer | Purpose |
|----------------|----------|----------|---------|
| `icon_keys.txt` — sorted, one kebab-case key per line, LF, no blanks | `backend/internal/event/iconkeys/` (generated by `frontend/scripts/generate-icon-keys.mjs`, checked in) | Go via `go:embed` | `validateIcon` membership check |
| `dynamicIconImports` keys | `lucide-react/dynamic` | Guest/admin renderers, sync test | Per-name lazy glyph rendering |
| `icons-data.ts` metadata (name, tags, categories) | `frontend/components/ui/` (vendored from registry) | Picker UI | Display, fuzzy search, category grouping |

**Invariants** (these are what make FR-006/007/008 true):

1. `picker-offered = icons-data ∩ dynamicIconImports` ⊆ `dynamicIconImports`
2. `backend-accepted = icon_keys.txt = dynamicIconImports` (enforced by the vitest sync
   test; regenerate on lucide-react upgrades)
3. `legacy 20 keys ⊂ icon_keys.txt` (enforced by a Go test — all 20 existing keys are
   standard Lucide slugs, so stored data needs no migration)
4. Renderers fall back to the `Info` glyph for any key outside `dynamicIconImports`
   (stale key after a future downgrade/rename) — page never breaks.

Note the picker may offer slightly **fewer** icons than the backend accepts (if
`icons-data.ts` lags the installed lucide version); that direction is safe — everything
offered is accepted. The reverse direction is what the sync test forbids.

## State / Transitions

`icon` has two states per block: unset (NULL) ⇄ set (catalog key). Transitions happen
only through the existing create/update admin endpoints; the picker's clear affordance
maps "set → unset" to submitting `icon: null`, exactly as today.

## Frontend state shape (unchanged wire contract)

Form-local: `icon: string` where `""` means none; submit maps `"" → null`. List/detail
reads: `icon: string | null` on `ActivityBlock` / `GuidelineBlock` in
`frontend/lib/types.ts`. `CONTENT_ICON_KEYS` in that file loses its "the whole catalog"
role and is retained only as the legacy-compatibility fixture for tests (or removed if
no longer referenced).
